# 🧠 Project Planning Template

A comprehensive template to structure and organize your projects effectively. This template integrates with the SK Project Management System and provides a standardized approach to project planning.

## How to Use This Template

### Option 1: Digital Project Creation
- Go to Projects → New Project → "Create from Template"
- Fill in the structured form with guided prompts
- Automatically get default milestones and tasks

### Option 2: Download Markdown Template
- Go to Projects → New Project → "Download Template (.md)"
- Use the markdown file for external planning
- Import content back into the system later

### Option 3: Manual Planning
Use the structure below as a guide for your project planning:

---

## 1. Project Overview
- **Project Name**: Clear, descriptive title that explains what this project is about
- **Purpose / Goal**: What are you trying to achieve? What problem are you solving?
- **Success Criteria**: How will you know when you've succeeded? Define specific, measurable outcomes

### Examples:
- **Purpose**: "Create a user-friendly mobile app for tracking daily habits"
- **Success Criteria**: "App launched with 100+ downloads, 4+ star rating, and key features working smoothly"

---

## 2. Key Considerations

### Stakeholders
- Who is involved or affected by this project?
- Who needs to approve decisions?
- Who will use the final deliverable?

### Constraints
- Time limitations (deadlines, availability)
- Budget restrictions
- Technical limitations
- Resource constraints

### Risks
- What could go wrong?
- How likely are these risks?
- What's your mitigation strategy?

### Dependencies
- What does this project depend on?
- What other projects or systems need to be completed first?
- What external factors could impact timeline?

---

## 3. Milestones
Break the project into major phases or checkpoints.

| Milestone | Description | Target Date | Owner | Success Criteria |
|-----------|-------------|-------------|-------|------------------|
| Project Setup | Complete planning and resource allocation | Week 1 | You | All planning documents complete, resources secured |
| Phase 1 Complete | [Define based on your project] | Week 4 | Team Lead | [Specific deliverable or outcome] |
| Mid-point Review | Progress assessment and adjustments | Week 6 | You | Review complete, adjustments documented |
| Final Delivery | Project completion and handover | Week 8 | You | All deliverables complete, stakeholders satisfied |

### Tips for Milestones:
- Keep them achievable and specific
- Include review points for course correction
- Assign clear ownership
- Link to specific deliverables

---

## 4. Action Plan
Detailed tasks to move the project forward.

| Task | Priority | Deadline | Status | Owner | Notes |
|------|----------|----------|--------|-------|-------|
| Define project scope | High | Day 3 | Not Started | You | Document boundaries and requirements |
| Research similar projects | Medium | Week 1 | Not Started | You | Learn from others' approaches |
| Set up project structure | High | Week 1 | Not Started | You | Create folders, tools, processes |
| Create initial prototype | High | Week 2 | Not Started | Developer | Basic version for testing |

### Priority Guidelines:
- **High**: Critical path items, blockers for other work
- **Medium**: Important but not urgent, can be adjusted
- **Low**: Nice to have, can be postponed if needed

---

## 5. Resources Needed

### Tools & Technology
- Software required (specific versions if important)
- Hardware or equipment needed
- Platforms or services required
- Development tools, design software, etc.

### People & Skills
- Team members needed and their roles
- External consultants or contractors
- Skills that need to be developed
- Training requirements

### Budget
- Personnel costs
- Software licenses or subscriptions
- Equipment purchases
- Marketing or operational expenses
- Contingency buffer (typically 10-20%)

### Knowledge & Training
- Skills that need to be acquired
- Training courses or resources
- Documentation to be created
- Knowledge transfer requirements

---

## 6. Tracking & Review

### Progress Checkpoints
- **Frequency**: How often will you review progress? (Daily standups, weekly reviews, monthly assessments)
- **Metrics**: What will you measure? (Tasks completed, budget spent, quality indicators)
- **Format**: How will you track? (Dashboard, reports, meetings)

### Adjustments & Flexibility
- Which aspects of the project can be adjusted if needed?
- What's the process for making changes?
- How much timeline flexibility exists?
- What scope can be reduced if necessary?

### Final Review & Learnings
- Post-project retrospective process
- Documentation of lessons learned
- Success factors to replicate
- Improvements for future projects
- Knowledge sharing with the team
